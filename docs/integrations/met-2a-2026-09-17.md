## Corrections to the contract, measured this session

### `isPublicDomain=true` on the search is not honoured

`/v1.1/search?q=war&tags=true&hasImages=true&isPublicDomain=true` returned
object **108646** (`"Uniform"`) and object **261944**
(`"[Battlefield at Vaux, France]"`), both of whose hydrated payloads say
`"isPublicDomain": false`.

This is not a variation on the P0 probe's "search totals are parameter-
sensitive" finding — it is a filter that silently does not filter. The
consequence is direct: **the public-domain gate must be applied to the hydrated
object, never to the query**, or a copyrighted image URL reaches a page. That is
where the provider applies it, and there is a test for it. The P0 report's
`isPublicDomain ⇒ primaryImage` hypothesis is unaffected either way — it was
about the object's own payload, which is exactly what is trusted here.

### The search's `objectIDs` is capped at 100 without `limit`

`total` reported 2,444 for *soldier* while `objectIDs` held 100. `offset` and
`limit` both work and page over a stable ordering (`offset=0&limit=5` and
`offset=5&limit=5` returned disjoint, consecutive slices of the same list), as
the P0 report found. Per D10, no search total anywhere is treated as a fact.

## Rules honoured

- **No image bytes.** `primaryImageSmall` is stored as a URL. Browsers loading a
  rendered page fetch those URLs themselves; nothing in this codebase does.
- **Credit travels with the image.** `creditLine` is captured on the same result
  as the image URL, in one map, never resolved separately.
- **Public-domain objects only.** Enforced on the hydrated object.
- **Bounded.** One page costs at most `1 + Met.scan_window()` = 26 requests, and
  the shared rolling budget caps the provider at 1,000 per hour.
